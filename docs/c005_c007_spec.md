# C-005 / C-007 — prose specification: interfaces and acceptance criteria

**Authorised as prose by Sol's Q-012 ruling** (*"documenting the interfaces and
acceptance criteria for C-005/C-007 in prose"*; *"a prose-only implementation
specification or review checklist for C-005/C-007 is allowed"*), scope restated
at D-125. **This document authorises nothing to run.** No source code, no

## C-005 — the grouped critic splitter

### Purpose

Partition the labelled configuration-conditions into the three canonical
splits so that the clustering the design created is respected **at
construction**: units that were given related data by design — a comparison
group — never straddle a boundary that separates training from evaluation
(D-039). The split is by **configuration and seed, never by transition**
(P Table 7: random splitting would leak, because transitions from one training
run are highly correlated). Three splits exist and are named separately
(S§W12 Tue): `train`, `validation` (early stopping and any tuning), and
`held_out` (touched first in Week 15, never revisited).

### Position in the pipeline

Upstream of the certified class balancer. The splitter produces the `split`
field that `critic/balance.py` consumes; the balancer stays
synthetic-inputs-only until this component exists (D-120, D-125). The split
names are **imported from the balancer's `CANONICAL_SPLITS`, never redefined**
— two sources for three names is how a `held-out`/`held_out` typo becomes
silent data loss (delta-54 history).

### Interface, in prose

**Input** — one record per attempted labelled unit:
`unit_id` (the content hash; the statistical unit, D-006/D-033),
`comparison_group_id` (D-039's key, built at D-039), intended class,
observed label (integer 0/1, or `ambiguous`/`undiagnosed`), and the
provenance C-007 needs (stage; seeds used by labelling).

**Registered parameters, fixed before any real label exists** (the D-115
precedent — the trace cap and balance seed were frozen exactly this way):
the held-out target respecting the plan's floor (**≥ 60 held-out units** of
≥ 300, P§10.7), a validation target, per-class floors implied by the W5 MDE
target on **min(N₀, N₁)** (S§W11 Fri), and a **split seed** — a new constant
in `constants.py`, requiring its own Change Record, **never caller-overridable**
(a frozen constant callers can replace is not frozen; delta-54 ruling).

**Output** — a **total and exclusive** mapping `unit_id → split` (every unit
assigned exactly once), plus a schema-versioned manifest: per-split × per-class
unit counts and group counts; the group→split mapping (the mapping, not a bare
set of names — D-118); surviving decidable counts and `min(N₀, N₁)` per split
against the W5 target; the input digest; the seed; `SPLIT_SCHEMA_VERSION`
starting at 1, bumped whenever fields **or their meaning** change — before any
real manifest exists, never after (the D-121 lesson, learned on version 1 of
the balance schema).

### Assignment semantics

1. **The unit of assignment is the whole comparison group.** Stratified by
   intended class so both classes reach every split; the design's groups are
   class-pure (240 groups, 125/115 by class — §1 design scale), so a group
   carrying two intended classes is an input-integrity violation and is
   **refused**, not stratified around.
2. **Deterministic and process-stable.** Selection order via a keyed stable
   hash over (seed, class, `comparison_group_id`) — the `blake2b` pattern the
   balancer uses, never Python's `hash()`, which is process-randomised while
   looking deterministic within one run (D-115).
3. **Undecidable units are assigned like any other** — exclusion is the
   balancer's job, downstream, per split (P§7.4) — but the manifest reports
   decidable counts, because the W11 Friday verification runs on surviving
   `min(N₀, N₁)`, never the total (S§W11 Fri, DEV-012).
4. **Fail closed, at the boundary, before any output exists** (the delta-54/55
   balancer history, all six-plus-three of it): refuse duplicate `unit_id`s;
   refuse labels outside {0, 1, ambiguous, undiagnosed} with booleans rejected
   before the integer check; refuse non-canonical split names anywhere; refuse
   a class emptied in any split (the balancer's m = 0 lesson: an empty split
   scores nothing and raises nothing downstream); refuse targets unreachable
   with whole groups, reporting the exact shortfall rather than quietly
   rebalancing. **No resampling, no duplication, no partial output.**

### Acceptance criteria — the tests that must exist when it is implemented

- **Property over every arm and stage**, parametrised — one arm passing is not
  evidence about another (D-055). For each test, ask what would make it fail
  (D-055/D-057/D-071); no assertion on a parameter name, a flag, or the
  mechanism that currently delivers the property.
- **The group invariant on real output:** the splitter's own output feeds the
  balancer's public `assert_groups_do_not_span_splits` unmodified, end-to-end
  — the same check, one implementation, not a re-statement of it.
- **Determinism across processes:** identical mapping under a different
  `PYTHONHASHSEED`, twice.
- **Stratification:** per-class counts within the declared targets;
  `min(N₀, N₁)` at or above the registered floor, or the run refuses.
- **Adversarial fixtures mirroring the balancer's certified history:** string
  `"0"`, `True`, `4.9` where integers belong; `held-out` for `held_out`; one
  content-hashed unit in two splits; a mixed-class group; an all-undecidable
  class.
- **Manifest cross-checked against inputs, not against itself** (D-072): every
  count recomputable from the mapping plus the input records; digests over the
  bytes actually delivered.

## C-007 — the confirmatory guard at every critic loader

### Purpose

Seeds below `CONFIRMATORY_SEED_BASE = 1000` are development data, permanently
excluded from the critic's training, evaluation and labels (D-034). Two of the
three call-site families are done — threshold calibration (D-090) and repair
acceptance (D-093). **The critic loaders remain**, W6–W11 work.

### Interface, in prose

Every loader that feeds the critic passes `require_confirmatory=True` to
`load_runs()`. The guard is **tied to the stage, never to a boolean a caller
flips**: a probe that legitimately wants development data labels itself
`pilot` rather than exempting itself (§6's standing wording, D-093's
precedent). Records missing stage or seed metadata **fail closed** — refused,
not defaulted.

### Acceptance criteria

- **A planted sub-1000-seed record cannot reach any critic path** — a positive
  refusal test, not an absence-of-failure test (D-054: a check that finds
  nothing proves nothing outside its coverage).
- **Coverage enumerated from the code, not from a list:** the test discovers
  critic-feeding loaders from the registry/call graph and asserts each carries
  the guard — a hardcoded list of loaders goes stale silently, and a fix in one
  layer is not a fix (D-056: the split that was implemented in collection and
  never carried into training).
- **The exemption path is exercised:** a `pilot`-labelled probe loads
  development data *and* is refused by every confirmatory consumer.

## What this specification does not do

It does not start implementation, fix the split targets' numeric values, or
create the split-seed constant — each of those is a scheduled or
Change-Record-gated act. If any statement here contradicts a certified
decision, **the ledger wins** and the contradiction should be reported rather
than resolved silently.
