# C-005 / C-007 — prose specification: interfaces and acceptance criteria

**Authorised as prose by Sol's Q-012 ruling** (*"documenting the interfaces and
acceptance criteria for C-005/C-007 in prose"*), scope restated at D-125,
corrected to Sol's delta-61 review (D-128). **This document authorises nothing
to run.** No source code, no executable tests, no data, no labels, no split
seed. Implementation begins at its scheduled time (W6–W11) or on fresh explicit
authorisation; the split seed the splitter needs is named below as requiring
its own future Change Record, not created. Every requirement carries its source.

---

## The distinction this specification is built on: intended class vs observed label

Sol's delta-61 review found the first version of this document conflating two
things that must stay separate — the error is corrected throughout, and stated
here once so it cannot recur silently.

- **`intended_class`** is **construction provenance**: the axis a unit was
  *built* on. Experiment 1 builds intended estimation-failure units;
  Experiments 2A/2B build intended hypothesis-class-failure units. It is known
  at configuration-enumeration time, and the design's planned counts are
  expressed in it — 240 comparison groups, **125/115 by intended class**,
  unit-level 150/150 intended; the reserve is 120/111 **by intended class**
  (D-092).
- **`observed_label`** is the **repair-derived critic target**: run both
  repairs, see which works. `0` = estimation failure (data repair works, model
  repair does not), `1` = hypothesis-class failure (the reverse), `ambiguous`
  (both), `undiagnosed` (neither) — the plan's Table 2. It does not exist until
  Month-2 labelling, and a unit built with one intended class can carry a
  *different* observed label, or an undecidable one.

**Everything about class balance, adequacy and `min(N₀, N₁)` is decided on the
observed label** (DEV-012: adequacy rests on surviving `min(N₀, N₁)`; intended
class is a *reporting* stratifier only, *"reported … by intended class"*).
Intended-class purity of a group is a construction fact; **observed-label
mixing within a group is scientific information, not an integrity violation.**

## C-005 — the grouped critic splitter

### Purpose

Partition the labelled configuration-conditions into the three canonical splits
so the clustering the design created is respected: units given related data by
design — a comparison group — never straddle a train/evaluation boundary
(D-039). The split is by **configuration and seed, never by transition**
(P Table 7: random splitting leaks, because transitions from one run are highly
correlated). Three splits, named separately (S§W12 Tue): `train`, `validation`
(early stopping and any tuning), `held_out` (touched first in Week 15, never
revisited).

### Position in the pipeline

The required order, with eligibility and balancing kept as **distinct** steps
(Sol, delta 61 — the balancer must not silently combine them):

1. **Split all attempted units** — every unit receives a split, for complete
   provenance;
2. **Report** ambiguous and undiagnosed counts **per split**;
3. **Exclude ineligible labels** at an explicit eligibility boundary — only
   observed `0`/`1` records pass;
4. **Pass the surviving observed-decidable records to the class balancer**
   (`critic/balance.py`), which balances and does no eligibility selection.

The balancer stays synthetic-inputs-only until this splitter exists (D-120,
D-125). Split names are **imported from the balancer's `CANONICAL_SPLITS`,
never redefined** — two sources for three names is how a `held-out`/`held_out`
typo becomes silent data loss (delta-54 history).

### Interface, in prose

**Input** — one record per **attempted** labelled unit: `unit_id` (content
hash; the statistical unit, D-006/D-033), `comparison_group_id` (D-039's key),
**`intended_class`** (construction provenance), **`observed_label`**
(`0`/`1`/`ambiguous`/`undiagnosed`), and the provenance C-007 needs (stage;
seeds used by labelling).

**Registered parameters, fixed before any real label exists** (the D-115
precedent): per-split targets, with the **held-out floor stated on surviving
observed-decidable units** — the plan's **≥ 60 held-out** is ≥ 60 *surviving
labelled* units of ≥ 300, not attempted or merely assigned (P§10.7); the
`min(N₀, N₁)` inferential floor from the W5 MDE simulation, **on observed
labels** (S§W11 Fri, DEV-012); and a **split seed** — a new `constants.py`
value requiring its own Change Record, **never caller-overridable** (a frozen
constant callers can replace is not frozen; delta-54). **The held-out floor is
not automatically applied to train and validation** — those take a split
requirement only if one is separately registered.

**Output** — a **total and exclusive** mapping `unit_id → split` over **all
attempted units** (each assigned exactly once, undecidable included, for
provenance), plus a schema-versioned manifest (see below).

### Assignment semantics

1. **The unit of assignment is the whole comparison group**, kept intact across
   the split boundary (D-039). A group carries one **intended class** by
   construction; a group spanning two **intended** classes is a
   *construction-integrity* error and is **refused** — but its **observed**
   labels may legitimately differ (0, 1, ambiguous, undiagnosed together), and
   that observed mixing is **never** refused.
2. **Allocation targets the surviving observed-decidable counts.** Model each
   group by its decidable observed count vector `(n0_g, n1_g)` (plus its
   ambiguous/undiagnosed counts, carried for reporting). A **deterministic
   constrained group allocator** assigns whole groups toward the registered
   per-split, per-observed-class targets. Intended class may be retained as a
   **secondary stratification or diagnostic** variable; it **cannot** substitute
   for the observed target.
3. **The stable hash is a tie-breaker, not the allocation rule.** Once groups
   have unequal sizes and mixed observed outcomes, sorting by
   `blake2b(seed, …, group)` alone does not hit the targets. The allocator is a
   deterministic constrained assignment; the `blake2b` key (never Python's
   `hash()`, which is process-randomised, D-115) resolves **otherwise-equivalent**
   choices only.
4. **Fail closed, at the boundary, before any output exists** (the delta-54/55
   balancer history): refuse duplicate `unit_id`s; refuse observed labels
   outside {0, 1, ambiguous, undiagnosed}, booleans before the integer check;
   refuse non-canonical split names anywhere; refuse a **mixed-intended-class**
   group; and when whole-group constraints make a registered target
   **infeasible**, refuse with the **exact shortfall** rather than splitting a
   group or rebalancing. **No resampling, no duplication, no partial output.**

### Manifest — both class concepts, observed named for every decision

Schema-versioned (`SPLIT_SCHEMA_VERSION` from 1, bumped whenever fields **or
their meaning** change, **before** any real manifest exists — the D-121 lesson,
learned on version 1 of the balance schema). It records, **per split**:

- **attempted** units;
- **observed** decidable-`0` and decidable-`1` counts (the critic-balance
  numbers);
- **ambiguous** and **undiagnosed** counts;
- **total surviving** held-out labelled units;
- **`min(N₀, N₁)` on observed labels** against the registered floor;
- **`intended_class`** counts, as construction diagnostics only;
- the group→split mapping (the mapping, not a bare set of names — D-118);
- the input digest and the seed.

**Every adequacy and `min(N₀, N₁)` statement names the observed labels
explicitly**; intended-class counts never stand in for them.

### Acceptance criteria — the tests that must exist when it is implemented

- **Observed vs intended kept distinct, tested directly:** an intended-class-pure
  group with mixed *observed* outcomes is **accepted** and its observed counts
  reach balancing; a **mixed-intended-class** group is **refused**. The
  adversarial fixture is labelled *mixed intended class*, never merely "mixed
  class".
- **Balancing hits observed targets:** per-split observed decidable counts within
  the declared targets; held-out surviving `min(N₀, N₁)` at or above the
  registered floor, or the run refuses with the exact shortfall.
- **Property over every arm and stage**, parametrised — one arm passing is not
  evidence about another (D-055). For each test ask what would make it fail
  (D-055/D-057/D-071); no assertion on a parameter name, a flag, or the
  mechanism currently delivering the property.
- **The group invariant on real output:** the splitter's own output feeds the
  balancer's public `assert_groups_do_not_span_splits` unmodified, end-to-end —
  one implementation, not a restatement.
- **Eligibility and balancing are separable:** undecidable records receive a
  split and appear in the per-split report, and are **excluded before** the
  balancer sees them; a test asserts the balancer receives only observed
  `0`/`1`.
- **Determinism across processes:** identical mapping under a different
  `PYTHONHASHSEED`, twice; and a fixture where the hash breaks a genuine tie,
  so the tie-breaker path is exercised rather than assumed.
- **Adversarial fixtures mirroring the balancer's certified history:** string
  `"0"`, `True`, `4.9` where integers belong; `held-out` for `held_out`; one
  content-hashed unit in two splits; a mixed-intended-class group; an
  infeasible target.
- **Manifest cross-checked against inputs, not itself** (D-072): every count
  recomputable from the mapping plus the input records; digests over the bytes
  delivered.

## C-007 — the confirmatory boundary for the critic

### Purpose

Seeds below `CONFIRMATORY_SEED_BASE = 1000` are development data, permanently
excluded from the critic's training, evaluation and labels (D-034). Two call-site
families are done — threshold calibration (D-090) and repair acceptance (D-093).
**The critic loaders remain**, W6–W11 work.

### Interface, in prose — resolving the delta-61 tension

The first version said both *"every loader passes `require_confirmatory=True`"*
and *"the guard is never a boolean the caller can flip."* Those are in tension;
Sol required it resolved. The resolution: **the confirmatory requirement is a
property of a critic-loading boundary, not a flag threaded through call sites.**

- A **confirmatory-only critic loader/boundary** enforces the requirement
  **internally and exposes no caller-overridable exemption.** Stage metadata is
  validated at that boundary; validation does **not** grant a critic consumer
  permission to weaken the guard.
- A **pilot probe** that legitimately wants development data uses a **separate
  development-data loading path** — and **every critic-facing consumer rejects
  that path's output.** The probe cannot reach the critic; it is not exempted,
  it is on a different road that dead-ends before the critic.
- Records missing stage or seed metadata **fail closed** — refused, not
  defaulted.

### Acceptance criteria

- **A planted sub-1000-seed record cannot reach any critic path** — a positive
  refusal test, not an absence-of-failure test (D-054).
- **Registry-authoritative coverage:** critic-facing consumers are discovered
  from an authoritative registry, and **adding an unregistered critic loader
  itself fails a test or invariant** — a hardcoded list goes stale silently, and
  a fix in one layer is not a fix (D-056).
- **The two paths are exercised and separated:** a `pilot` probe loads
  development data through the development path *and* is rejected by every
  critic-facing consumer; no single call both loads development data and reaches
  the critic.

## What this specification does not do

It does not start implementation, fix the split targets' numeric values, or
create the split-seed constant — each is a scheduled or Change-Record-gated act.
If any statement here contradicts a certified decision, **the ledger wins** and
the contradiction is reported, not resolved silently.
