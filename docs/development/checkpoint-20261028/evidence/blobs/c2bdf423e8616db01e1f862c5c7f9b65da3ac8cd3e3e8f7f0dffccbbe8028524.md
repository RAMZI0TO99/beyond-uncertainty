## Fail-closed presence and shared pause fix

File.Exists/Test-Path are not used as known-clear evidence by this version.
Present uses throwing File.GetAttributes on the exact normalized absolute path.
A returned attribute value means PRESENT, including a directory or reparse entry
at a pause path. Only explicit FileNotFoundException/HRESULT2 or
DirectoryNotFoundException/HRESULT3 may establish tentative absence. Then a
bounded<=16-level parent walk must find an accessible direct directory ancestor;
its unknown/denied/error/reparse state refuses. This prevents a missing or
unavailable drive/ancestor from being silently called clear. The bounded<=4
exception unwrapping recognizes only PowerShell runtime/reflection wrappers.

successful effect or pass. The same predicate guards all existence decisions,
not only the pause loop. Only the expressly admitted cleanup-only path may
publish honest failed custody metadata after such a refusal.

This uses ordinary managed metadata APIs, not C# compilation, native file-ID
measurement, pause-content parsing or proof of atomic future absence.

[GetAttributes](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.getattributes?view=net-10.0)
documents throwing lookup/permission failures; [Exists](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.exists?view=net-10.0)
can report false on lookup errors. These references support the guard design,
not a runtime pass or a claim that synchronous OS calls cannot stall.
